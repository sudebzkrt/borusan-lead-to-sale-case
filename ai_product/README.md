# Lead Intelligence Assistant

An AI-assisted data product for sales advisors: ranks open leads by conversion probability, explains each score,
and drafts the next action. It consumes the Gold layer only.

```
gold.fact_leads + fact_interactions + fact_test_drives + fact_offers + dim_*
        │
        ▼  train_lead_scorer.py  (snapshot features, HistGradientBoosting, temporal validation)
gold.lead_scores  (score, band, reasons, note signals)
        │
        ▼  app.py  (Streamlit)      ──►  llm.py (optional: OpenAI-compatible LLM for summary / next action / draft message)
```

| File | Role |
|---|---|
| `signals.py` | Turkish keyword rules → structured note signals (price objection, went quiet, buying signal, …). Same schema as the LLM extractor. |
| `train_lead_scorer.py` | Builds point-in-time snapshots of closed leads, trains, validates (temporal split), scores open leads, writes `gold.lead_scores` and `model/*`. Also importable into Fabric as a notebook (`.ipynb`). |
| `llm.py` | Provider-agnostic LLM calls with a template fallback so the demo never depends on a key. |
| `app.py` | Four pages: ranked leads · lead detail + next best action · model card · data lineage. UI in Turkish. |
| `model/` | `lead_scorer.pkl`, `metrics.json`, `feature_importance.csv`, `calibration.csv` (regenerated by the trainer). |

## Run

```
REPO_ROOT=$PWD python ai_product/train_lead_scorer.py     # needs data/gold from 03_gold_star_schema
streamlit run ai_product/app.py
```
Optional LLM: create `ai_product/.env` with `LLM_API_KEY=...` (and `LLM_BASE_URL`, `LLM_MODEL` for non-OpenAI providers).

## Results (seed 42)

Temporal split at 2026-03-01, 17.2k training snapshots, 8.9k test snapshots.

| Slice | AUC | PR-AUC | Lift @ top 10% | Precision @ top 10% (base) |
|---|---|---|---|---|
| All test snapshots | 0.82 | 0.53 | 2.9× | 60% (21%) |
| Before offer stage | 0.84 | 0.47 | 3.7× | 53% (14%) |
| After offer stage | 0.74 | 0.57 | 1.9× | 64% (34%) |

The pre-offer slice is the one that matters: after an offer everyone already knows the lead is warm.

## Why it is built this way

* **Snapshots, not final states** — features computed as of a random moment in each closed lead's life; the outcome-recording note is removed. Without this the model "learns" that offers cause sales and is useless on the open pipeline.
* **Rules for scale, LLM for the last mile** — 15k leads × daily LLM calls is cost and latency for nothing; coarse signals are enough for ranking. The LLM adds value where a human reads: one lead, one summary, one drafted message.
* **Ablation explanations** — replace one feature with its baseline, re-score, report the delta. Faithful to this model, readable by a sales manager. SHAP is the upgrade path.
* **Fallbacks everywhere** — no key → template mode; no Fabric → local parquet. The demo does not depend on the network.

## Known limits

Synthetic notes are cleaner than real CRM notes. Dealer/advisor effects in the model penalise leads at weaker dealers — fine for ranking within a dealer, unfair across dealers; production would neutralise or report them separately. Retraining cadence (monthly, as a pipeline step after Gold) and drift monitoring are not implemented.
